2. Evaluación de calidad y deuda técnica
De los 5 estándares, 3 no se cumplen y 2 se cumplen parcialmente. El núcleo (Domain ← Application ← Infrastructure) respeta la dirección de dependencias, pero la presentación la saltea y habla con la base de datos.

2. Clean Architecture
Parcial
Proyectos bien separados, pero Desktop referencia Infrastructure y 14 pantallas usan el DbContext en code-behind. Coexisten dos patrones de datos (Repository+UoW+MediatR y IApplicationDbContext); Application depende de EF Core
3. Aislamiento multi-tenant
No cumple
0 de 10 entidades tienen TenantId/ComercioId. No existe entidad Comercio, HasQueryFilter ni middleware de tenant
4. Seguridad y calidad
No cumple

5. Persistencia Code-First
Parcial

Nota sobre el estándar 1: .NET 8 dejó de tener soporte el 10/11/2026. Recomiendo actualizar el estándar a .NET 10 LTS; en ese punto el repo ya está alineado.

4. Resumen ejecutivo
Puntos fuertes reutilizables
• Modelo de dominio rico: constructores con invariantes, setters privados, baja lógica y auditoría de fechas en las entidades principales.
• Value objects Money y Sku, y la base Entity<TId> / ValueObject.
• Venta con estructura fiscal argentina: totales gravado, no gravado e IVA, y campos AFIP (punto de venta, CAE, vencimiento).
• Arqueo de caja en el dominio: CajaSesion.CerrarSesion calcula sobrante o faltante.
• Piezas transversales listas para cablear: ValidationBehavior de MediatR, GlobalExceptionMiddleware con ProblemDetails, validador de CrearProducto.
Fallos críticos / bloqueantes
1.  Ausencia total de aislamiento multi-tenant.
2.  Cliente de escritorio con acceso directo a la base de datos central.
3.  Contraseñas con SHA-256 sin sal y credenciales semilla en el código.
4.  Sin JWT ni RBAC: cualquier usuario autenticado accede a todo.
5.  Flujo de venta roto por IDs ficticios; stock y arqueo inconsistentes.
6.  Stack fuera de estándar: WPF y SQL Server en lugar de Blazor WASM y PostgreSQL.
Recomendación final: reiniciar el esqueleto (Opción B)
El multi-tenancy es una propiedad del núcleo, no un agregado: toca cada entidad, índice único, consulta y token. Sumado a que el 75 % del código es WPF no reutilizable, alinear la base actual cuesta más que construir el esqueleto correcto y portar el dominio. Plan propuesto:
1.  Nueva solución en .NET 10 LTS: Domain, Application, Infrastructure, WebAPI y Blazor WASM, con proyectos de tests desde el inicio.
2.  Núcleo multi-tenant: entidad Comercio, TenantId en todas las entidades, ICurrentTenant leído del claim JWT, HasQueryFilter global, interceptor que asigna el tenant al guardar e índices únicos compuestos (TenantId + Sku).
3.  Seguridad: JWT con políticas por permiso, hashing con BCrypt, rate limiting, CORS y secretos en User Secrets / variables de entorno.
4.  PostgreSQL con Npgsql, una migración inicial limpia y concurrencia optimista con xmin.
5.  Portar el dominio actual corrigiendo la deuda: métodos DescontarStock / IngresarStock, FKs de Venta, códigos de comprobante como enum, todas las entidades heredando de Entity<Guid>.
6.  Tests de aislamiento entre tenants como criterio de aceptación de cada módulo antes de construir POS, inventario y cuenta corriente.
